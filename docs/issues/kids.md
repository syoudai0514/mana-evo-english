# [教材 P1] 子供の5つの冒険ワールド：60アクティビティ・300フレーズ

## 目的
子供が「また相棒に会いたい」と思える3〜5分の遊び。累積の成功をほめ、連続日数を失った罪悪感を与えない。

## 制作数
- 5ワールド（おうち/どうぶつ/たべもの/まち/ふしぎな自然）×12回＝60アクティビティ。
- 1回につき目標フレーズ5つ＝300枠（復習による再登場は許可、unique phrase ID数も報告）。
- 1回に導入1・3つのやりとり・成功の言葉1・日本語救済2。相棒2体の性格差を付ける。
- 初回バッチ：おうちワールド3回、15フレーズ。レビュー後12回、残り48回へ。

## 実装の場所・形式
src/data/topics.js / scenes.js / guess.js / prompt.js、子供ホームの既存 free/play/guess 導線。まず lesson ID→既存モード設定の対応を作り、巨大なプロンプトに全部埋め込まない。

## 個別の完了条件
- Pre-A1/A1で「聞くだけ→一語→短文」を選べる。日本語や沈黙にも優しく進行。
- 自由会話は生成内容を完全制御できると説明しない。個人情報・所在地・秘密を質問しない。
- 翌日に同じ問題を押しつけず、未完了から再開・既習から復習できる。
- 英語/訳/ヒント/絵の意味が一致し、子供の声と親の操作で実機確認する。

## 共通の受入条件・引き継ぎ
- `docs/HANDOFF.md` と `docs/CONTENT_SPEC.md` を先に読む（体験刷新 PR のブランチに追加）。Issue に指定した最小バッチから進める。
- ID は固定し、出典・権利・難易度・学習目標・想定時間・日本語訳・レビュー状態を付ける。AI 生成だけで reviewed 扱いにしない。
- 最初のバッチをアプリに接続して検証してから増産。件数チェック、重複、答えの一意性、訳、音声との一致を確認。
- npm test / npm run build と変更範囲のブラウザ確認を実施。未検証の音声や本番接続は明記。
- 完了数/目標数、変更ファイル、検証コマンド、次の最小タスクを docs/HANDOFF.md に記録してコミット。モデルが変わってもこの Issue 単位で再開できる状態にする。
