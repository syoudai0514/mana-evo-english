# [教材 P1] フォニックス：26文字見直し＋CVC60語＋聞き分け24組

## 目的・制作数
既存の「きょうのもじ」を文字名と音が混ざらない体系へ育てる。
- 既存26文字を専門確認（新規26文字を重複追加しない）。文字名・代表音・口の形・例語を別フィールド化。
- CVC 60語（短母音5種×12語）、聞き分け24組。合計110学習項目。
- 26文字の文字名/音/例語＝78音声、CVC60音声、聞き分け48音声＝186音声枠。音の単独録音が不適切なケースは専門家判断を記録。
- 初回：文字5つの見直し＋CVC10語＋聞き分け4組。

## 実装の場所
src/data/letters.js、Home の LetterCard、Stickers の ABC アルバム。

## 完了条件
- カタカナ表記を発音の正解と扱わない。文字名と音のボタン・説明を分ける。
- 各素材は台本/権利/話者/アクセント/音量情報、オフライン状態を持つ。
- 文字だけでも進められ、誤答に罰を与えない。再生完了とタップを区別して記録する。

## 共通の受入条件・引き継ぎ
- `docs/HANDOFF.md` と `docs/CONTENT_SPEC.md` を先に読む（体験刷新 PR のブランチに追加）。Issue に指定した最小バッチから進める。
- ID は固定し、出典・権利・難易度・学習目標・想定時間・日本語訳・レビュー状態を付ける。AI 生成だけで reviewed 扱いにしない。
- 最初のバッチをアプリに接続して検証してから増産。件数チェック、重複、答えの一意性、訳、音声との一致を確認。
- npm test / npm run build と変更範囲のブラウザ確認を実施。未検証の音声や本番接続は明記。
- 完了数/目標数、変更ファイル、検証コマンド、次の最小タスクを docs/HANDOFF.md に記録してコミット。モデルが変わってもこの Issue 単位で再開できる状態にする。
