# [基盤 P1] 本番音声・認証・子供の保護・データ保存を検証/強化

## コードレビューの根拠
- supabase/functions/english-talk/index.ts の制限はプロセス内Map。ephemeral token発行にモデル設定制約がない。実際の権限と現行API仕様を確認する必要がある。
- src/screens/Parent.jsx のPINはlocalStorage平文＋計算問題の再設定で、本人認証や暗号化ではない。
- src/lib/auth.js は独自refresh実装。実セッションで多重タブ・logout/refresh競合を確認していない。
- 音声は外部へ送信される。現行の案内・保存期間・会話記憶の同意を確認する。

## 実装/検証量
- 8シナリオ：正常ログイン/期限切れ/多重タブ/ログアウト中refresh/マイク拒否/通信断復帰/iOS割込/保存容量不足。
- 利用者単位の永続レート制限、同時接続上限、トークン権限・モデル制限、入力サイズ制限を現行仕様に合わせる。
- 保護者向けに送信先/保存場所/削除/端末共用時の注意を実装。エラーのログに会話・トークンを残さない。
- 子供データの削除/エクスポート/クラウド同期は既存Issue #1と整合。新規保存基盤を重複作成しない。

## 完了条件
テスト用アカウントでブラウザ→Edge→Gemini→結果を検証し、失敗時は原因と復帰導線を表示。「無料/無制限」は料金とクォータを一次情報で確認するまで掲げない。Supabase接続先を推測して移行しない。

## 共通の受入条件・引き継ぎ
- `docs/HANDOFF.md` と `docs/CONTENT_SPEC.md` を先に読む（体験刷新 PR のブランチに追加）。Issue に指定した最小バッチから進める。
- ID は固定し、出典・権利・難易度・学習目標・想定時間・日本語訳・レビュー状態を付ける。AI 生成だけで reviewed 扱いにしない。
- 最初のバッチをアプリに接続して検証してから増産。件数チェック、重複、答えの一意性、訳、音声との一致を確認。
- npm test / npm run build と変更範囲のブラウザ確認を実施。未検証の音声や本番接続は明記。
- 完了数/目標数、変更ファイル、検証コマンド、次の最小タスクを docs/HANDOFF.md に記録してコミット。モデルが変わってもこの Issue 単位で再開できる状態にする。
