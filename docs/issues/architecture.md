# [基盤 P2] 会話画面の責務分割・アクセシビリティ・PWA回帰検証

## 現状
Talk.jsx は1,125行で接続/録音/字幕/会話状態/UI/保存を扱う。画面遷移はAppのstateで、履歴URLがない。既存CSSと刷新CSSが共存している。

## 小さく進める作業
1. 現行mockの開始/発話/終了/復帰をブラウザテストで固定。
2. 接続管理・音声・会話進行を3hookに分割、表示を字幕/ヒント/操作部の3部品へ。APIを変えず1分割1PR。
3. 共通色/余白/typographyへ既存画面を順番に移行し、旧CSSの不要規則を削除。
4. 学習中の戻る/再読込/ブラウザバック時の扱いを決め、履歴復元を実装。

## 検証マトリクス
幅320/390/768/1280、キーボード、スクリーンリーダー、文字200%、reduced motion、Safari/iOSの録音とPWA更新。
オフライン起動/静的素材/取得済み音声/未取得音声を区別。service worker の固定URL画像更新と旧キャッシュ掃除を検証。

## 完了条件
既存40ロジックテストと刷新E2Eを維持、実音声の開始/中断/再接続/終了を実機で確認。見た目だけのsnapshotを成功の根拠にしない。共通マイク操作のキーボード対応も完了する。

## 共通の受入条件・引き継ぎ
- `docs/HANDOFF.md` と `docs/CONTENT_SPEC.md` を先に読む（体験刷新 PR のブランチに追加）。Issue に指定した最小バッチから進める。
- ID は固定し、出典・権利・難易度・学習目標・想定時間・日本語訳・レビュー状態を付ける。AI 生成だけで reviewed 扱いにしない。
- 最初のバッチをアプリに接続して検証してから増産。件数チェック、重複、答えの一意性、訳、音声との一致を確認。
- npm test / npm run build と変更範囲のブラウザ確認を実施。未検証の音声や本番接続は明記。
- 完了数/目標数、変更ファイル、検証コマンド、次の最小タスクを docs/HANDOFF.md に記録してコミット。モデルが変わってもこの Issue 単位で再開できる状態にする。
