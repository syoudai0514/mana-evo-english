# [基盤 P1] TOEIC 全7パートの出題形式・共有素材・計時を実装

## 現状と問題
src/data/adult.js の TOEIC_PARTS は Part 2/3/4/5/語彙。Quiz は Part 2/3 の音声を中心とする。Part 1/6/7 を含む公式試験形式の完全対応ではない。predictScore は未校正の独自換算であり本番予測に使わない。

## 実装量
- Part 1 写真1枚＋音声4択、Part 2 音声3択、Part 3 会話＋3問、Part 4 説明文＋3問、Part 5 短文穴埋め、Part 6 文書＋4問、Part 7 単一/複数文書＋複数問の7レンダラー。
- stimulus / question 分離、共有音声・画像・文書、解答保留、戻る、再開、練習と模試の表示を実装。
- 各Part最低1セット＋Part7の単一/二文書/三文書＝最低9 fixtureセット（量産しない）。
- 練習は解答後解説、模試はListening約45分/Reading75分の設計と一時停止ルールを明記。

## 完了条件
- 音声未取得・通信切断・再生不可を未回答/誤答と混同しない。
- 解答記録にquestion ID/version/part/skill/時間/ヒント使用を保持。
- 共通素材が問題遷移で途中から重複再生されない。キーボード/320px/横長文書で確認。
- 既存履歴を移行し、非互換データを消さない。正答率を主に表示し未校正スコアで目標達成を宣言しない。
- 画像/音声が読めない時の代替・復帰、バックグラウンド復帰をテスト。

## 共通の受入条件・引き継ぎ
- `docs/HANDOFF.md` と `docs/CONTENT_SPEC.md` を先に読む（体験刷新 PR のブランチに追加）。Issue に指定した最小バッチから進める。
- ID は固定し、出典・権利・難易度・学習目標・想定時間・日本語訳・レビュー状態を付ける。AI 生成だけで reviewed 扱いにしない。
- 最初のバッチをアプリに接続して検証してから増産。件数チェック、重複、答えの一意性、訳、音声との一致を確認。
- npm test / npm run build と変更範囲のブラウザ確認を実施。未検証の音声や本番接続は明記。
- 完了数/目標数、変更ファイル、検証コマンド、次の最小タスクを docs/HANDOFF.md に記録してコミット。モデルが変わってもこの Issue 単位で再開できる状態にする。
